case study 01

ParkPass

Live Code

A visitor parking permit app for London, in the style of RingGo or MiPermit. Households share a monthly allowance of visitor hours, issue passes to saved vehicles in a couple of taps, and top up when they run low. The interface is designed around UK road signage: parking-sign blue for the hours that matter most, and real UK number plates wherever a vehicle appears.

Next.js TypeScript Supabase / Postgres GraphQL Tailwind Base UI Playwright + axe
accessibility, built in

Every colour token is contrast-checked against WCAG AA, colour never carries meaning on its own, search is a full ARIA combobox, and dialogs trap and return focus. It's verified by axe on every page in Playwright, plus manual keyboard-only and NVDA screen reader testing. The tradeoff: hand-built components take longer, so I reached for Base UI only where accessibility is hardest to get right by hand, in the dialogs.

a decision, and the tradeoff

Issuing a pass originally read the balance in the browser and wrote it back, so two people issuing at once could spend the same hours twice. I moved issuing, top-ups and household creation into Postgres functions that check and update in a single transaction, and added token verification and household-scoped authorisation to every GraphQL resolver. Business rules now live in one place, at the cost of splitting logic between TypeScript and SQL.

what I'd change next

Allowances currently belong to the household, but councils set them per address. Next I'd move the balance onto each location so every address follows its own council's rules, and replace instant member adds with invites that have to be accepted.

case study 02

Geostorm

Live Code

A geolocation-based weather forecasting app, built on the Open-Meteo API, with reverse geocoding and a units system (metric/imperial) that persists in the URL rather than local state - so a forecast can be shared or bookmarked exactly as viewed. Visual design is from a Frontend Mentor challenge; the geolocation logic, API integration, and component architecture are mine.

Next.js TanStack Query Base UI CSS Modules
a decision, and the tradeoff

I built the unit selector as a reusable Base UI Select/Menu component rather than a one-off dropdown, so the same pattern could be reused anywhere else the app needed a similar control. It took longer to build than a simple native select, but it meant every future selector in the app inherited the same accessible, keyboard-navigable behaviour for free.

Both are live and built end to end - ParkPass including the visual design; Geostorm's engineering, on top of a Frontend Mentor design. Happy to walk through either in more depth.
